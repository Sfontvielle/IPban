# GymLog — трекер тренировок с AI-тренером

Персональное приложение для iPhone: шаблоны тренировок, каталог упражнений,
запись подходов в зале, история, аналитика прогресса, личные рекорды и AI-тренер,
который работает на ваших реальных данных.

Разработка ведётся **на Windows**, запуск — **на iPhone через Expo Go**.
Mac и Xcode не нужны.

Проект собран на **Expo SDK 54** (React Native 0.81, React 19.1) — под ту версию
Expo Go, которая стоит у вас на телефоне.

## 1. Что нужно установить (один раз)

Откройте **PowerShell** (обычный, не от администратора):

```powershell
winget --version                                   # проверить, что winget есть

winget install --id OpenJS.NodeJS.LTS -e
winget install --id Git.Git -e
winget install --id Microsoft.VisualStudioCode -e
```

**Закройте PowerShell и откройте заново**, иначе новые программы не появятся в PATH.

```powershell
node -v      # нужно v20.19.4 или выше
npm -v
git --version
```

На iPhone установите **Expo Go** из App Store.

## 2. Запуск проекта

```powershell
cd C:\dev\gymlog
npm install
npx expo start
```

1. В терминале появится **QR-код**.
2. Windows спросит про доступ Node.js к сети — **разрешить для частных сетей**.
3. На iPhone откройте **стандартную Камеру**, наведите на QR и нажмите подсказку.
   (На iOS сканируют именно Камерой, не внутри Expo Go.)
4. Первая загрузка занимает 10–40 секунд.

Компьютер и iPhone должны быть в **одном Wi-Fi**. Если сеть гостевая или с изоляцией
клиентов — запускайте так:

```powershell
npx expo start --tunnel
```

> Важно: папка проекта должна лежать по пути без пробелов и кириллицы и **не в OneDrive**.
> Правильно: `C:\dev\gymlog`.

При первом запуске появится экран `GymLog · загружаю каталог упражнений` — это
одноразовый импорт 179 упражнений в базу. Дальше открывается приложение с пятью вкладками:

| Вкладка | Что там |
|---|---|
| 🏠 Главная | Кнопка «Начать тренировку», статистика недели, свежие рекорды, локальный анализ |
| 📋 Тренировки | Ваши программы, создание и редактирование шаблонов |
| 🔍 Каталог | Поиск и фильтры по 179 упражнениям, карточка с техникой, свои упражнения |
| 📈 Прогресс | История · Прогресс · Тело (три сегмента вверху) |

Настройки — иконка ⚙︎ в правом верхнем углу Главной.

## 4. Проверка, что всё работает (сценарий MVP)

1. **Каталог** → найдите «жим лёжа» → откройте карточку. Должна быть техника, шаги, ошибки, советы.
2. **Тренировки** → «Новая тренировка» → название «Грудь» → «+ Добавить» → выберите
   *Жим штанги лёжа*, *Жим гантелей лёжа*, *Сведение рук в кроссовере* → «Сохранить».
3. **Начать тренировку** → выберите «Грудь».
4. В жиме введите `80` и `8`, нажмите ✓ — запустится таймер отдыха и сработает вибрация.
   Заполните три подхода: 80×8, 80×8, 80×7.
5. **Завершить тренировку** → появятся итоги: длительность, подходы, объём, рекорды.
6. Через несколько дней (или сразу — второй тренировкой) снова начните «Грудь».
   Возле жима в колонке «Прошлый» будет `80×8  80×8  80×7`.
7. Введите `82.5 × 8` → после завершения приложение отметит **новый рекорд**.
8. **Прогресс → Прогресс → Жим штанги лёжа** — на графике появится новая точка.

Если этот сценарий проходит — базовый MVP работает.

## 6. AI-тренер (необязательно)

AI — надстройка. Без него работает **всё**, кроме чата и разбора тренировок.

Ключ AI-провайдера **нельзя** класть в приложение — его легко извлечь из бандла.
Поэтому в `server/` лежит минимальный прокси для Cloudflare Workers (бесплатный тариф).

Инструкция — в [`server/README.md`](server/README.md). Кратко:

```powershell
cd C:\dev\gymlog\server
npm install
npx wrangler login
npx wrangler kv namespace create RATE_LIMIT   # id вписать в wrangler.toml
npx wrangler secret put ANTHROPIC_API_KEY
npx wrangler secret put DEVICE_TOKEN
npx wrangler deploy
```

Полученный адрес вписать в приложении: **Настройки → AI-тренер → Адрес вашего AI-сервера**,
там же включить переключатель «Включить AI».

**Как это устроено:** модель просит данные через инструменты, но сами инструменты выполняются
**на телефоне** — SQL идёт в вашу локальную базу. На сервер уходит только текст вопроса
и результат конкретного запроса. Вся история остаётся на устройстве.

**Главное правило:** все числа считает код приложения (`src/analytics/`), AI их только объясняет.
Модель не имеет права ничего вычислять — это прописано в системном промпте
и обеспечено тем, что в контекст кладутся уже готовые значения.

## 7. Структура проекта

```
gymlog/
├─ src/
│  ├─ app/              маршруты expo-router (тонкие файлы-обёртки)
│  ├─ db/               соединение, миграции, импорт каталога
│  ├─ repositories/     ЕДИНСТВЕННОЕ место, где есть SQL
│  ├─ services/         сценарии: тренировка, бэкап, уведомления, подсказки
│  ├─ analytics/        чистые функции: объём, 1ПМ, рекорды, застой (покрыты тестами)
│  ├─ ai/               провайдер, контекст, инструменты, чат, разбор, память
│  ├─ features/         экраны, сгруппированные по функциям
│  ├─ components/ui/    дизайн-система
│  ├─ stores/           zustand: активная тренировка, таймер, настройки
│  ├─ theme/            токены и темы
│  └─ utils/            даты, единицы, форматирование
├─ assets/catalog/      exercises.json — каталог (генерируется скриптом)
├─ scripts/             сборка и валидация каталога
├─ server/              AI-прокси (Cloudflare Worker)
└─ docs/architecture.html   архитектурный документ этапа 1
```

Правило слоёв: **UI → hooks/stores → services → analytics/repositories → SQLite**.
Экран никогда не пишет SQL, аналитика никогда не ходит в базу.

## 8. Что уже сделано

**Данные и надёжность**
- SQLite со схемой на 20+ таблиц, система миграций через `PRAGMA user_version`
- Каждый подход пишется в базу немедленно; после вылета приложения тренировка восстанавливается
- Снимки полей в истории: переименование или удаление упражнения не ломает прошлые тренировки
- Мягкое удаление, `created_at`/`updated_at` — база готова к синхронизации и экспорту

**Каталог**
- 179 упражнений с русскими и английскими названиями, синонимами, мышцами, оборудованием,
  паттерном движения, техникой, ошибками и советами
- Поиск FTS5 с префиксами и нормализацией (ё → е) + резервный поиск, если FTS недоступен
- Фильтры по мышцам и оборудованию, свои упражнения, алгоритмический подбор замены
- Восемь типов измерения: вес × повторы, свой вес, с доп. весом, с помощью, только повторы,
  время, вес × время, расстояние

**Тренировка**
- Таблица подходов с колонкой «Прошлый раз», крупные поля, цифровая клавиатура
- RIR / RPE (переключается в настройках), типы подходов (разминочный / рабочий / дроп)
- Таймер отдыха на метке времени — переживает сворачивание приложения,
  вибрация и локальное уведомление
- Добавление, замена, перестановка и удаление упражнений прямо во время тренировки

**Аналитика**
- Объём с учётом типа измерения и веса тела; разминочные подходы не считаются
- Расчётный 1ПМ по формуле Эпли, вынесен в отдельный слой
- Пять видов рекордов, определение застоя, сравнение тренировок, частота, объём по мышцам
- 35 тестов на критические расчёты

**Оптимизации**
- Импорт каталога — многострочные вставки вместо ~4800 отдельных запросов;
  первый запуск заметно быстрее
- Списки шаблонов — один запрос вместо запроса на каждый шаблон
- Карточки упражнений в активной тренировке обёрнуты в `React.memo` со стабильными
  обработчиками: отметка подхода не перерисовывает остальные упражнения

**AI**
- 16 инструментов чтения данных, выполняются локально
- Разбор тренировки после завершения (кешируется), чат, память с ручным управлением
- Прокси на Cloudflare Workers, провайдер заменяем через один интерфейс

**Данные пользователя**
- Экспорт JSON и CSV, импорт резервной копии, очистка AI-истории и полное удаление данных

## 9. Возможные ошибки и что делать

| Симптом | Причина | Решение |
|---|---|---|
| QR отсканирован, но «не удаётся подключиться» | Брандмауэр или разные сети | Разрешить Node.js в брандмауэре; проверить Wi-Fi; иначе `npm run start:tunnel` |
| `Project is incompatible with this version of Expo Go` | Expo Go обновился до более новой SDK | Перевести проект: `npx expo install expo@latest --fix`, затем `npm run start:clear` |
| Странные ошибки после установки пакетов | Кеш Metro | `npm run start:clear` |
| `EPERM`, `file is locked` | Проект в OneDrive или антивирус | Перенести в `C:\dev\gymlog`, добавить папку в исключения |
| Приложение зависло на «загружаю каталог» | Сбой импорта | Смахнуть приложение в Expo Go и открыть заново; при повторе — `npm run start:clear` |
| Пусто в «Прогрессе» | Ещё нет завершённых тренировок | Проведите и завершите тренировку |
| AI пишет «не настроен» | Нет адреса сервера | Развернуть `server/` и вписать адрес в настройках |

## 10. Про версию SDK

Проект зафиксирован на **SDK 54**, потому что Expo Go на вашем iPhone именно этой версии.
Если App Store однажды обновит Expo Go до более новой SDK, приложение перестанет
в нём открываться — это лечится одной командой:

```powershell
cd C:\dev\gymlog
npx expo install expo@latest --fix
npm run start:clear
```

Делать это стоит осознанно, между этапами работы, а не посреди отладки.
Чтобы Expo Go не обновлялся сам: **Настройки iPhone → App Store → Обновления приложений** выключить.
